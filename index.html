One workbench for every database you work with

DataNest connects to PostgreSQL, MySQL, SQL Server, Oracle, SQLite, DuckDB, MongoDB and more, with SQL that knows your schema, a results grid built for real data, ER diagrams, schema migrations and server tools. Use it inside VS Code, or as a desktop app on Windows, macOS and Linux.

SQL that knows your schema

Completion of tables, columns and functions comes from the database you are connected to, with their types. Diagnostics appear as you type, the formatter tidies a script in one keystroke, and Explain shows how any statement will run.

  • Run the statement under the cursor with Ctrl+Enter
  • History, saved queries and snippets for every connection
  • Transactions, savepoints and isolation levels at hand

See how a query runs

Explain shows the plan as text, a tree or a graph. Explain Analyze runs the statement, rolls it back and shows where the time went and which row estimates were off, so you know which step to fix first.

  • Row-estimate accuracy, with the likely causes
  • Buffers, reads from disk and the slowest steps
  • Compare two plans node by node

Results you can work with

Sort and filter on the server, page through large results, and edit cells with every change staged and its SQL shown before anything is committed. Follow foreign keys, edit JSON, group and pivot, and compare two results side by side.

  • Import and export CSV, JSON, Excel, Arrow and Parquet
  • Copy tables from one database to another

Dashboards over your queries

Turn any query into a widget: a line or bar chart, a gauge with warning and critical marks, a single number or a table, laid out on a grid and refreshed by hand or on a timer. A dashboard is a JSON file in your workspace that names its connection but never its host or password, so you can commit it with your SQL.

  • Alert rules with thresholds, started from templates
  • Notifications on screen, by email, webhook, Slack or Teams
  • A PostgreSQL monitoring dashboard in one step

See the shape of your data

Draw an ER diagram of a schema with its foreign keys, and the relationships DataNest infers from names, types and data where no constraint says so. Design tables with the SQL previewed before it runs.

  • Hierarchical, force-directed and manual layouts
  • Impact analysis before you change a table
  • Export diagrams as images

Change schemas safely

Compare a database with a snapshot kept in your repository, a branch's checkout or another database. Every difference is listed, with the incompatible ones flagged, and the migration plan shows each statement with the locks it takes and the data it could destroy before you apply it.

  • Renames detected, not dropped and re-created
  • Try a migration in a sandbox first
  • History and rollback of every migration

Know what your server is doing

Sessions and running queries, who blocks whom as a graph, query statistics and execution plans, index advice, bloat and vacuum, replication, users and roles, backups, server logs and sizes, where the database offers them: PostgreSQL's in depth, and SQL Server's deadlocks and Agent jobs, MySQL's InnoDB, Oracle's scheduler and MongoDB's sharding too.

  • Cancel a query or end a session, with the SQL shown first
  • Live panels that refresh on their own
  • Query baselines that flag a regression

AI, on your terms

DataNest is an MCP server: give Claude, Cursor, Copilot in VS Code or another assistant your connections and choose, per connection, what it may read or change. A change it proposes waits for you, with the exact statement, its risk and what it touches, and runs only once you approve it.

  • Sensitive columns kept out of what it reads
  • No writes to a production connection, ever
  • A transcript of every call

More of DataNest

  • Compare data

    Compare two tables or two queries row by row, across schemas or databases: what was added, removed or changed, each changed row as it was and as it is. Then sync the differences, with the SQL shown first.

  • Copy between databases

    Copy a table into another database, even another kind. Each column's type is mapped and what it may lose is said, before a dry run and the copy.

  • Index advice with evidence

    The advisor reads pg_stat_statements, table sizes and index usage, suggests the indexes your slowest statements need and finds duplicate and unused ones, each with its evidence, its uncertainty and the statement it would run.

  • Design on the diagram

    Add tables, columns and keys on the ER diagram. Every change shows its risk, the locks it takes and its SQL, and nothing runs until you review and apply it.

  • A migration, step by step

    Each step of a plan says what it risks, the lock it takes and whether it can be undone, above the forward and rollback SQL that will run.

  • Every tool beside its connection

    A PostgreSQL connection lists its tools in the side bar, fourteen here. The activity view shows connection use and every session live, here two idle in a transaction for minutes.

Tools for every database

  • SQL Server, down to its deadlocks

    Sessions, locks, statements, Agent jobs, availability groups, index advice and the deadlocks the server recorded, each with its victim and the statements caught in it.

  • MongoDB pipelines, stage by stage

    Build an aggregation pipeline a stage at a time, switch stages on and off, and see each stage's output before you open the whole pipeline in the editor.

  • Oracle's scheduler at a glance

    Every job with how it last ran, when it runs next and its schedule in words. The same views read MySQL's events and SQL Server Agent, with replication and sharding where the database has them.

  • Automation

    Macros, scheduled jobs whose steps wait for each other, and a headless runner for CI, such as a check for schema drift.

  • Spatial data

    PostGIS geometries on a map, spatial queries and filters, and diagnostics for invalid shapes.

  • Inside SQLite

    Pages, the write-ahead log and integrity checks of a SQLite file, with a hex view down to the byte.

  • Curated plugins

    Signed plugins from a reviewed catalog, each with the permissions it asks for shown before you install it.

  • Private by default

    Connections stay on your machine and their passwords in a secret store. No telemetry unless you turn it on.
